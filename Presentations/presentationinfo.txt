REVIEW ALL THE PRESENTATIONS




Goal: Indoor mobile robot that performs SLAM and autonomous navigation using wheel odometry + visual odometry on an NVIDIA Jetson Nano A02 (4GB). Raspberry Pi Camera v2 is used for vision (Jetson is the only compute unit).

Main hardware: Jetson Nano, Raspberry Pi Camera v2, TT 48:1 gearbox motors (differential drive), SparkFun Qwiic pHAT (40-pin) + Qwiic Motor Driver, SparkFun Micro OLED (status), optional 433 MHz antenna for telemetry.

Software stack: NVIDIA JetPack (for Jetson), ROS 2 (recommended Humble or the NVIDIA-supported distro), Isaac ROS (optional/accelerated), Navigation2 (Nav2) for planning, and a visual SLAM/VO package (e.g., ORB-SLAM2/3 or RTAB-Map). Use robot_localization (EKF/UKF) to fuse wheel odom and visual odom.

Localization approach:

Publish wheel-encoder odometry (nav_msgs/Odometry) from the motor driver.

Run monocular visual SLAM/VO on camera frames to produce pose and map.

Fuse both sources in robot_localization so Nav2 gets a robust pose estimate; SLAM provides the /map for Nav2.

OLED & Qwiic usage: Qwiic pHAT provides I²C connectivity for the motor driver and OLED. OLED shows status/debug (pose, errors, mode).

Key implementation steps:

Mechanically assemble chassis, mount Jetson + camera; wire motors to Qwiic motor driver and Qwiic pHAT.

Flash Jetson with JetPack; install ROS 2 and Isaac/SLAM packages.

Implement/configure motor driver node (I²C) and wheel-encoder odom publisher.

Calibrate camera intrinsics and launch camera ROS node.

Launch visual SLAM/VO node and verify map + camera pose in RViz.

Configure robot_localization to fuse wheel and visual odom.

Launch Nav2 with the generated map for planning and obstacle avoidance.

Test and iterate: tune wheel parameters, SLAM settings, and EKF covariances. Optionally simulate in Isaac Sim first.

Notes / recommendations: Calibrate wheel radius and baseline, tune sensor covariances in robot_localization, and reduce camera resolution/frame rate if Jetson performance needs easing. If monocular scale drift becomes an issue, consider stereo/depth sensors.
